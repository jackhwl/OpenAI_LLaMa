# <MCP学习小组> · 第二章课堂练习：最小可行工作流（MVW）
## 1. 任务名称
基于参考文献生成组会周报
---
## 2. 任务背景（为什么选择它？）
- 任务背景
  每周课题组举行组会时，每位成员需要汇报过去一周的阅读进展、实验进展、遇到的困难以及下一步计划。传统方式是由学生手动整理已阅读的参考文献，并结合实验记录编写周报，耗时且容易遗漏关键信息。  
  使用“基于参考文献生成组会周报”任务，可以自动化地从已标注、整理好的文献库中提取关键信息（如研究问题、方法、结论等），并结构化地生成周报初稿，提升汇报准备的效率与系统性。
- 说明为什么它是你们的高频任务
 1. **周期性需求**：组会每周固定举行，周报需按时提交，属于高频、刚需任务。
 2. **文献积累量大**：研究生阶段需持续跟踪领域前沿，每周阅读文献数量较多，手动整理负担重。
 3. **规范化输出**：导师要求周报结构清晰、重点突出，自动化生成有助于保持格式统一与内容完整。
 4. **时间优化**：将重复性整理工作自动化，节省时间用于深入思考与实验设计，提升科研效率。
---
## 3. 输入（Input）
- 原始材料来源
  **参考文献库**（如 Zotero、EndNote 或本地 PDF 文件夹）
  **文献笔记或注释**（如高亮、批注、总结段落）
  **实验记录或数据**（如有相关实验进展）
  **研究计划表或待办事项清单**
- 必要的约束条件
  每周阅读文献数量不少于 3 篇
  文献需属于同一研究方向或课题相关
  周报字数控制在 800–1200 字
  需在组会前一天完成并提交
- 角色/受众
  **汇报人**：在读研究生（你本人）
  **听众**：导师、课题组其他成员（包括博士生、硕士生）
  **潜在审阅者**：合作研究者、实验室负责人
---
## 4. 结构化方式（Structure）
- 大纲结构
1. **本周阅读总结**
    
    - 文献列表（作者、年份、标题）
        
    - 核心研究问题
        
    - 研究方法与技术路线
        
    - 主要结论与启发
        
2. **实验进展（如有）**
    
    - 已完成实验
        
    - 遇到的问题与解决方案
        
    - 初步结果与分析
        
3. **困难与反思**
    
    - 理解上的难点
        
    - 方法或工具上的障碍
        
4. **下周计划**
    
    - 继续阅读的文献方向
        
    - 实验计划

## 5. SCORE Prompt（核心提交内容）
```text
S（Setting）：你是一名在读研究生，正在准备每周课题组组会汇报。你需要基于过去一周阅读的参考文献和实验进展，撰写一份结构清晰、重点突出的周报。
C（Context）：组会每周举行一次，导师和课题组成员会听取每个人的进展汇报。周报需体现文献理解深度、研究推进逻辑和问题意识。已有参考文献库和实验记录作为原始材料。
O（Objective）：生成一份可用于组会展示的周报草稿，内容需涵盖文献总结、实验进展（如有）、困难反思与下周计划，字数在 800–1200 字之间。
R（Requirements）：
- 使用中文撰写，风格正式、学术  
- 按“大纲结构”组织内容   
- 引用文献时注明作者与年份  
- 如无实验部分，可省略“实验进展”章节  
- 困难部分需真实具体，体现思考过程 
- 下周计划需具体可行，与本周内容衔接
E（Evaluation）：
- 结构完整、逻辑清晰  
- 内容真实、无虚构信息   
- 重点突出、避免流水账   
- 语言简洁、符合学术汇报风格
- 能体现研究推进的连续性与问题意识
```
## 6. 迭代记录（Iterate）
- 第一轮迭代日志
 1. 发现的问题（Problem）：
    1. 结构过于正式，缺乏研究进展逻辑
        - 周报采用了综述式结构，更像文献报告而非进展汇报
        - 缺少“本周实际做了哪些工作”的清晰陈述
        - “实验进展”部分虽然注明“无新实验”，但未说明是否进行了复现、代码理解等准备工作
    2. 文献引用方式不符合要求
        - 原文要求“引用文献时注明作者与年份”，但周报中部分引用格式不一致
        - 如“Li et al. (2024)”在文中未明确对应文献出处
 2. 修正指令（Fix Prompt）：
    请基于以下要求重写周报：
    1. **结构调整**：
        - 明确区分“本周已完成工作”和“文献阅读收获”    
        - 将文献理解融入个人研究推进中，而非单独列出
    2. **引用规范化**：
        - 确保所有引用格式统一为“作者(年份)”    
        - 如有必要可在文末添加简要参考文献列表
 3. 改进后的输出（Improved Output）：
     - 突出了个人实际完成的工作（环境配置、代码复现）
     - 将文献理解融入个人研究思考中,并规范了文献格式
- 第二轮迭代日志
1. 发现的问题（Problem）：
     1. 下周计划不够具体可行
        - “理论梳理与问题凝练”缺乏可衡量的输出    
        - “实验设计初步方案”未说明具体使用什么代码库、预期产出
     2. 语言风格过于综述化
        - 部分段落直接翻译文献内容，缺乏个人理解的提炼  
        - 未体现“研究推进的连续性”
2. 修正指令（Fix Prompt）：
   请基于以下要求重写周报：
    1. **内容具体化**：
        - 说明本周具体做了哪些工作（如复现代码、整理笔记、调试环境等）
        - 困难部分要体现个人在复现/理解中的具体卡点
        - 下周计划要具体到可执行的任务项
    2. **语言风格调整**：
        - 采用第一人称叙述，体现个人思考过程
        - 避免大段文献摘抄，重点提炼对个人研究有帮助的见解
3. 改进后的输出（Improved Output）：
    - 困难部分更具体（显存问题、理论困惑）
    - 下周计划更可执行（具体任务、预期产出）
    - 增加了“需要讨论的问题”环节，体现组会互动性

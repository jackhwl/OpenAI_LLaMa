
## 1. 任务名称

「研速报」—— 基于实验数据自动生成研究进展周报

## 2. 任务背景

| 项目        | 说明                                  |
| --------- | ----------------------------------- |
| **为什么选它** | 研究生每周需要向导师汇报研究进展，包括实验结果、遇到的问题、下周计划等 |
| **真实场景**  | 几乎每个工作日或每周都需要提交进度汇报，内容格式相对固定但繁琐重复   |
| **核心价值**  | 将碎片话的文档变成有内容有逻辑的报告，从繁琐的进度汇报中解放时间    |

## 3. 输入（Input）

原始材料来源：实验数据记录、代码运行日志、文献笔记、会议记录

必要约束条件：时间周期（本周）、研究阶段（中期/后期）、汇报形式（书面/口头）

角色/受众：导师、课题组会议

## 4. 结构化方式（Structure）

表格结构：数据表格→问题列表→任务列表

信息分类方式：

完成的工作量

取得的研究成果

遇到的问题和挑战

下周工作计划

## 5. SCORE Prompt（核心提交内容）

```

S（Setting）：你是研究生，需要为导师准备本周研究进展汇报材料

C（Context）：本周完成了[具体实验/分析工作]，获得了[数据结果]。当前处于研究[阶段]，需要向[导师/会议]进行汇报

O（Objective）：生成一份条理清晰、重点突出的研究进展报告，全面展示本周工作成果和问题

R（Requirements）：

- 结构包括：本周工作总结、主要成果展示、遇到的问题分析、下周工作计划

- 突出关键数据和重要发现

- 明确列出需要导师指导和帮助的问题

- 提供具体的下周工作目标和时间节点

- 语言简洁明了，避免冗长描述

E（Evaluation）：

- 工作总结的全面性和准确性

- 成果展示的清晰度和说服力

- 问题分析的深度和具体性

- 工作计划的可行性和明确性

- 整体结构和逻辑性

```


# 第一轮迭代日志

## 发现的问题（Problem）：


1. 实验数据展示过于技术化，缺乏学术意义解读

	- 报告直接列举了大量技术指标和性能参数，但未说明这些数据在学术研究中的意义
	
	- 缺少对实验结果与研究假设关系的分析
	
	- 数据呈现方式不够直观，缺乏图表可视化

2. 进度评估维度不全面

	 - 未体现实验阶段与整体研究目标的关联性
	
	-  缺少与相关文献对比的定量分析


## 修正指令（Fix Prompt）：

请基于以下要求重写研究进展报告：


1. 数据分析深度提升：

	- 不仅展示实验数据，还要解读数据背后的学术意义
	
	- 结合研究假设，分析实验结果是否支持原定理论
	
	- 增加对异常数据的深度分析和原因探讨
	
	- 研究进展评估维度扩展：


2. 增加研究方法创新性的评估维度

	- 明确实验阶段对整体研究目标的贡献度
	
	- 提供与相关文献的定量对比分析

  

## 改进后的输出（Improved Output）：

- 增加了"数据学术解读"部分，连接实验数据与研究意义

- 新增了"研究创新性与文献对比"章节

- 提供了实验进展对整体研究目标贡献度的量化评估

  
# 第二轮迭代日志

## 发现的问题（Problem）：


问题诊断和技术难题分析不够深入

- 实验失败原因分析停留在表面现象，未涉及系统性问题

- 技术瓶颈描述过于概括，缺乏具体技术细节

- 缺少对潜在替代方案的深入评估

  

2. 后续工作计划与当前问题关联性不强

- 下周计划与前序实验问题脱节，缺乏连续性

- 问题解决路径规划不够具体，可操作性不强

- 风险评估和对策准备不足

  

## 修正指令（Fix Prompt）：

请基于以下要求重写研究进展报告：

1. 问题分析深度加强：

	- 建立问题树状结构，从表象分析到根本原因
	
	- 详细记录调试过程中的技术细节和关键发现
	
	- 系统性地评估不同解决方案的优劣和可行性


2. 工作计划与问题关联性强化：

	- 基于当前实验问题制定有针对性的下周计划
	
	- 明确问题解决的阶段目标和里程碑
	
	- 制定详细的风险评估和应对策略


3. 改进后的输出（Improved Output）：

	- 创建了"技术问题深度分析"部分，包含根本原因分析和技术细节记录
	
	- 问题树状结构清晰地展示了问题表象与核心原因的关系
	
	- 下周计划直接对应前序实验阶段的问题和挑战
	
	- 增加了"技术路线评估表"，系统比较不同解决方案的优劣
	
	- 制定了详细的风险登记表和应对策略

## Reflect
- MCP 是否必要？
MCP 在需要获取最新外部信息或实时数据时是必要的，例如研究行业最佳实践案例、获取最新研究成果或访问动态更新的资源。然而，对于基于现有知识体系的任务（如基础理论学习），MCP 并非绝对必要。如果本地知识已涵盖所需内容，可以避免调用 MCP 以提高效率 [基于知识]。

- 哪些信息其实可以只靠本地知识？

基础理论和框架定义：例如生成式思维的核心概念（如发散思维、收敛思维）或知识工作流的基本模型（如 PKM 系统设计），这些内容在本地知识库中已有系统化总结。
历史或静态信息：如经典案例、已验证的方法论或通用流程（例如信息处理的标准步骤），这些信息变化较慢，本地知识足够支撑。

结构化任务：例如设计个人知识工作流原型或验证理论，这些步骤主要依赖内部逻辑和已有知识，无需外部输入 [基于知识]。

- 下次是否可以减少 MCP 调用？

是的，下次可以减少 MCP 调用。具体策略包括：

优先使用本地知识：在任务规划阶段，评估信息需求，如果内容属于基础理论、静态知识或可推导的框架（如行动计划中的 Step 1 和 Step 3），则直接依赖本地资源，避免不必要的 MCP 调用。

优化调用时机：仅当任务涉及动态或外部依赖时（如研究最新实践案例，类似行动计划中的 Step 2），才调用 MCP。例如，通过预定义规则或阈值（如“信息时效性超过一年时才调用 MCP”）来减少频率。

缓存和复用结果：对于重复性任务，将 MCP 获取的外部资料存储在本地知识库中，后续直接复用，避免重复调用 [基于知识]。

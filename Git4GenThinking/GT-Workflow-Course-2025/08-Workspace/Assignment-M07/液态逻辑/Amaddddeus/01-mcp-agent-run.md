## Reflect

### 1. MCP 是否必要？

**视情况而定，但本次实验中是必要的。**

- 必要性：学习目标是了解“强化学习的最新进展”。本地知识库（Obsidian）中存储的是历史知识，可能无法涵盖最新的研究动态、技术新闻或实时数据。MCP 提供的外部搜索能力，可以填补“本地知识时效性”的空白。因此，对于获取“最新”信息这个特定需求，MCP 是必要的。

### 2. 哪些信息其实可以只靠本地知识？

稳定的、已归类的、个人积累的知识，都优先依赖本地知识。

- 基础概念与理论：例如“什么是神经网络”、“监督学习与无监督学习的区别”等经典知识。
    
- 个人学习笔记和总结：我之前对某个技术点的理解、阅读论文后的心得、项目经验的总结等。这些是高度个性化的知识，外部来源无法提供。
    
- 实验步骤和代码片段：在之前实验中验证过的可靠代码和操作流程。
    
- 课程讲义和教学大纲内容：已经下载并存储在Vault中的课程资料。
    

核心原则：Obsidian 是“唯一事实源”。所有经过我验证、筛选、认为有价值的信息，最终都应沉淀到本地知识库中，成为下次决策时可依赖的“内部知识”。

### 3. 下次是否可以减少 MCP 调用？

应该更有目的地调用，目标是“减少不必要的调用”，而不是“减少调用次数”。

- 建立明确的触发条件：下次任务开始时，我应该和 Agent 一起先进行更严格的 **Evaluate（评估）**：
    
    - 问题一：“这个问题的答案在我的本地知识库中存在吗？是否足够新？”
        
    - 问题二：​ “我需要的信息是动态的、实时的，还是需要从海量公开资料中检索的？”
        
    - 只有当两个答案都明确指向需要外部信息时，才触发 MCP 调用。
        
    
- 批量获取，一次处理：​ 如果确实需要外部信息，可以尝试让 MCP 一次性提供多条相关要点，然后我进行集中筛选和整理，而不是频繁地、零散地发起多次调用。
    
- 强化人工筛选环节： 本次实验让我体会到，MCP 返回的信息需要经过我的判断。下次我会更注重对比外部信息与本地知识的异同，决定哪些真正值得写回Obsidian，避免信息污染。

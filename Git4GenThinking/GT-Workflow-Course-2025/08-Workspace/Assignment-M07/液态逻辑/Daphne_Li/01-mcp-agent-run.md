## Planning

### 目标（Goal）
- 通过一次完整的实验流程，学习并内化“生成式思维”在知识工作流中的应用方式
- 理解并实践：如何将零散信息组织为可检索、可评估、可行动、可反思的知识系统
- 掌握以 Obsidian 为载体的人在回路（Human-in-the-loop）Agentic Workflow

---

### 作用范围（Scope）
- 涉及内容：
  - 课程讲义中关于 RAG、GraphRAG、Action Chain 与 Agentic Workflow 的核心概念
  - 1 条外部学习材料（如论文或相关技术资料），作为具体学习与实践对象
- 不涉及内容：
  - 不引入额外自动化工具或插件
  - 不进行自动写回、自动合并或无人监督的知识修改
  - 不追求模型级别的自动推理或代码实现

---

### 完成标准（Done Criteria）
- 已在 Obsidian 中形成一条**可复现的结构化学习路径**，包括：
  - 明确的知识分块（Chunking）与概念卡（Concept Nodes）
  - 基于 GraphRAG 的关系组织与人工推理路径
  - 至少一份结构化的行动计划（Action Plan，Dry-run）
  - 一条完整的反思记录（Daily Reflection）
- 能够清晰说明：
  - 学习过程中 Agent 做了哪些判断
  - 哪些决策由人介入完成
  - 反思如何反向影响下一轮 Evaluate


## Evaluate

### Step 1：理解学习目标与生成式知识工作流
- 评估内容：明确“生成式思维 + 知识工作流”的学习目标与整体框架
- 判断依据：依赖课程讲义与已有知识结构
- 结论：信息充足，无需外部补充  
✅ 不需要 MCP

---

### Step 2：引入具体学习材料作为实践对象（需要 MCP）
- 评估内容：确定用于实践的 1 条外部学习资料（如论文或技术文章）
- 判断依据：本地知识库中不存在该原始材料
- 结论：需要从外部获取高质量输入作为学习“原材料”  
⚠️ 需要 MCP（仅用于资料获取）

---

### Step 3：对资料进行结构化处理与评估
- 评估内容：对已引入材料进行 Chunking、概念抽取与结构评估
- 判断依据：材料已进入本地系统，后续工作依赖人工理解与判断
- 结论：属于本地知识组织与 Evaluate 行为  
✅ 不需要 MCP

## Act —— 调用 MCP（人机回路）

- [x] 调用 MCP 获取外部资料  
  在 Cherry Studio 中启用 ModelScope Hosted MCP，
  向 Agent 请求 1 条与“生成式思维 / 知识工作流”相关的外部学习资料要点，
  MCP 的作用仅限于**提供原始信息输入**，不参与后续判断与决策。

- [x] 人工筛选并整理为学习要点  
  对 MCP 返回的资料要点进行人工审阅与筛选：
  - 去除与当前学习目标无关的信息
  - 保留可用于理解生成式思维与知识工作流的核心观点
  - 将筛选后的要点整理为结构化学习要点，而非直接复制原文

- [x] 写入本地实验文件  
  将人工筛选后的学习要点写入对应实验文档，
  作为后续 Chunking、概念抽取与 Evaluate 的输入材料，
  并明确标注其来源为“外部资料（经人工筛选）”。

---

### 行为说明（Act 阶段约束）
- MCP 仅作为**信息获取工具**被调用一次
- 所有取舍、理解与结构化工作均由人完成
- Agent 不对知识库进行自动写回或结构修改
- 本阶段输出结果将进入下一轮 Evaluate 与 Reflect


## Reflect —— MCP 使用反思

- **MCP 是否必要？**  
  是必要的，但仅在“外部原始资料输入”这一特定阶段。  
  本次实验中，MCP 的作用是为学习任务提供一条高质量的外部信息来源，
  以避免在缺乏材料的情况下进行空泛推理。

- **哪些信息其实可以只靠本地知识？**  
  学习目标的理解、知识结构的设计、Chunking 策略、概念边界判断、
  行动计划（Dry-run）的生成以及反思总结，
  均可以仅依赖本地知识库与课程讲义完成，
  不需要额外调用 MCP。

- **下次是否可以减少 MCP 调用？**  
  可以。  
  当本地知识库中已积累足够的外部资料与概念卡后，
  后续相似学习任务可直接复用已有 Memory，
  仅在遇到真正的信息缺口时才再次调用 MCP。

---

### 反思结论
MCP 在本实验中被证明是一种**“受控、一次性的信息补充手段”**，  
而非 Agent 持续依赖的能力。  
智能体的核心价值，仍然来自于结构化知识组织与人类在回路中的判断与反思。

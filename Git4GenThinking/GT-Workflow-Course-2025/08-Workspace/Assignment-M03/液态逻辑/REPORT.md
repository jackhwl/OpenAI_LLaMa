# 液态逻辑实验报告（REPORT.md）

## 一、实验目标与工作流总览
**目标**：验证“提示词作为软协议（Soft Protocol）”在复杂学术分析任务中，通过 Schema + Validator 的方式，是否能显著提升输出稳定性、可复用性与工程可控性。

**工作流**：
1. 非结构化 Prompt 直接生成结果  
2. 观察 Baseline 问题  
3. 设计 JSON Schema  
4. 编写结构化 Prompt  
5. 使用 Validator 自动校验  
6. Critic → Refine 迭代  

---

## 二、Baseline 现象：非结构化输出的问题

来自 `01_prompt_unstructured.md` 的典型问题：

- **字段缺失或顺序混乱**：模型常遗漏“复现难点”或“研究局限”部分  
- **粒度不一致**：有的回答停留在摘要级，有的过度展开细节  
- **不可编程**：输出为自然语言段落，无法被下游程序消费

示例片段（节选）：
> “这篇论文在 Object Navigation 领域具有一定创新性……”  
（后续未系统覆盖所有分析维度）

---

## 三、Schema 设计：字段选择理由

Schema 文件：`02_schema.json`

设计原则：
- **原子性**：每个字段只表达一个清晰语义（如 `core_mechanism`）
- **类型约束**：枚举 + min/maxLength 保证输出质量下限
- **自描述性**：字段名即分析问题本身，降低提示歧义

例如：
- `contribution_level` 使用 enum，防止“含糊其辞的创新评价”
- `reading_depth_assessment` 强制模型进行**自我认知校准**

---

## 四、结构化提示策略

结构化 Prompt：`03_prompt_structured.md`

关键策略：
- **角色锁定**：明确“论文精读博导”身份
- **定界符**：INPUT 区域与指令区严格分离
- **输出协议**：明确“必须是单一 JSON 对象”

为何有效？  
→ Prompt 不再只是“提问”，而是**接口协议说明书**。

---

## 五、评价机制

### 1. Validator 校验
使用 `05_validator.py` 基于 Draft7 JSON Schema：
- 自动检测字段缺失
- 自动检测长度 / 枚举违规
- 支持批量样本校验

结果：
- 非结构化输出：❌ 无法校验
- 结构化输出：✅ 可100%程序化验证

### 2. （可选）Judge 评分
可在 Validator 之后引入 LLM-as-Judge，对内容深度进行二次评分。

---

## 六、迭代日志：Critic → Refine

**Round 1 问题**：
- `_thought_chain` 过短
- `relation_to_landmark_works` 数量不足

**Refine 策略**：
- 在 Prompt 中显式加入字数与数量约束说明

**结果对比**：
- 通过率：0% → 100%
- 人工修改成本：显著下降

---

## 七、结论

**“提示词作为软协议”的关键工程收益**：

> 👉 把不稳定的自然语言生成，转化为**可验证、可组合、可迭代的工程接口**。

这使 LLM 从“聊天工具”升级为：
- 结构化知识生产模块
- 研究工作流中的自动化节点
- 可持续演进的智能系统组件

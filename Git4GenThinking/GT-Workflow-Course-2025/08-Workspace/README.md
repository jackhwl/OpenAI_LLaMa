
# 学员作业提交的工作空间

> 📌 这里是每个小组的 **作品仓库**,所有与课程相关的作业、实验结果、项目交付物，**统一存放在本目录**。

## 1. 目录用途说明

`08-Workspace/` 是本课程学员提交课后练习内容的目录，用于：

- 提交各模块的课堂练习与作业；
- 存放小组项目的中间版本与最终交付物；
- 记录实验日志、Prompt 迭代记录、工作流草图等。

## 3. 小组作业命名规范

### 3.1 文件命名原则

统一采用：

```text
<GroupName>-<ArtifactName>.md
```

示例：

- `银河护卫队-MVW.md`（第二章：最小可行工作流）
- `AlphaTeam-Structured-Input.md`（第三章：结构化输入笔记）
- `StarBuilders-Agent-Config.md`（智能体配置说明）

命名要求：

- `<GroupName>` 使用你们在课程中统一报备的小组名称；
- 文件名尽量用 **中文小组名 + 简短英文/中文描述**；
- 不要使用空格，可使用中划线 `-` 连接；
- 一个小组在同一模块下 **原则上只保留一个最终版本文件**。

### 3.2 模块内推荐结构（以 M02 为例）

```text
08-Workspace/
  └── Assigment-M02/
        └── 银河护卫队-MVW.md             
```

## 4. 协作与提交流程（Fork → 修改 → PR）

本课程采用接近真实开源项目的协作模式（参见仓库根目录 README）。推荐流程：

1. **Fork 仓库**

    - 由小组长 Fork 课程主仓库到自己的 GitLink 账号下。

2. **Clone 到本地**

    - 小组成员从队长仓库 Clone，一起在 `08-Workspace/` 下工作。

3. **在对应模块目录新增或修改文件**

    - 确保路径正确，例如：  
        `08-Workspace/M02-Workflow/银河护卫队-MVW.md`

4. **Commit 信息规范**

    建议使用以下格式：

    ```text
    [M02] 银河护卫队 提交 MVW 初稿
    [M02] 银河护卫队 更新 MVW 互评后版本
    [M03] AlphaTeam 提交结构化输入笔记
    ```

5. **Push 到队长仓库**

    ```bash
    git push origin main
    # 或者是你们约定使用的开发分支
    ```

6. **由队长向课程主仓库发起 Pull Request**

    PR 标题规范：

    ```text
    [银河护卫队] 提交 M02 MVW 最终成果
    ```

    PR 内容建议包含：

    - 本次提交涉及的模块与文件路径；
    - 主要变更内容（如：新增 MVW、根据 Issue 反馈迭代等）；
    - 对应的 Issue 链接（如果有互评）。


---

## 5. Issue 与互评（推荐实践）

虽然作业最终以 PR 为准，但我们推荐使用 Issue 做中间互评与讨论：

- 在主仓库 `Issues` 中，使用课程提供的 Issue 模板；
- 标题示例：`[M02] 银河护卫队 提交 MVW 互评请求`；
- 文内附上你们在 `08-Workspace/` 中的文件路径与关注点。

## 1. 课程概述

### 1.1 课程简介

在生成式AI时代，信息处理方式、知识创造方式与认知工作方式发生根本变革。AI不再只是回答器，而是可被调度的智能执行节点；人与AI关系从“提问-回答”演变为“设计-执行”。传统知识学习以记忆为中心，而**生成式思维以推理与结构化调度为核心**，通过工作流组织AI，使知识从素材流向成果。

本课程面向未来知识工作者，旨在帮助学习者：

- 从“会问AI”升级到“能调度AI”
- 从“完成一次生成”升级到“构建可复用工作流模板”
- 最终实现——**构建并交付一个可运行的AI智能体（Agent）**

 课程以生成式思维为核心，以知识工作流为方法论，通过任务驱动学习与Git协作式教学，让学生在实践中理解人机协作、形成可复用的创作流程，并最终完成一次作品交付与公开展示。

### 1.2 课程目标

本课程采用“**先完成、再升级**”的设计策略：

- 先保证学习者能够真实完成一次生成式工作闭环
- 再在此基础上，逐步揭示生成过程背后的系统结构与工程逻辑

课程并不要求所有学习者都进入最高阶能力，而是提供一条**清晰、连续、可选择的能力演进路径**。

### 1.2.1 基础成果目标

完成课程基础阶段（模块 01–04）后，学习者将能够：

1. **建立生成式思维的认知模型：** 理解生成式 AI 的工作方式，完成从“向 AI 要答案”到“为生成过程设计结构”的思维转变，形成稳定的人机协作认知框架。
2. **掌握生成式知识工作流的构建方法：**  能够将复杂任务拆解为可执行的生成流程，理解并运用知识工作流的关键环节（输入、结构化、生成、迭代、表达）。
3. **熟练设计结构化Prompt与提示链：**  能够使用结构化提示工程方法，将模糊意图转化为 AI 可执行的输入协议，形成可复用、可迁移的 Prompt 模板与 Prompt Chain。
4. **完成一次可交付的最小可行工作流闭环（MVW）：**  独立完成一次从输入准备、生成执行、迭代优化到成果输出的完整人机协作闭环，产出可展示、可复用的知识成果。
5. **形成可持续复用的个人工作方法：**  将生成式思维与知识工作流方法内化为个人能力，而非停留在工具或模板层面。

> 📌 **说明**：   上述目标本身已构成一门完整课程，学习者在完成该阶段后，即可获得明确、稳定、可迁移的生成式知识工作能力。

### 1.2.2 进阶系统目标（能力拓展｜在基础之上的进阶）

在完成基础成果目标的前提下，课程进一步为有能力与意愿的学习者提供**进阶系统能力的拓展路径**。完成进阶阶段（模块 05–07）后，学习者将进一步能够：

1. **将知识工作流提升为 Agentic Workflow：**  理解生成式工作从“单次生成流程”向“具备持续行动能力的工作系统”的转变，掌握行动链、反思机制与任务状态管理等关键概念。
2. **构建最小可行智能体（MVA）及其运行环境：**  理解智能体与 Prompt / RAG 的本体差异，能够在现实工程约束下，设计并运行一个可理解、可迭代的最小可行 Agent。
3. **理解并使用多智能体协作结构：**  掌握角色拆分、协作通信与任务分工的基本思想，避免将复杂任务压缩到单一智能体中。
4. **初步理解 MCP 等协议化协作机制：** 从系统视角理解多智能体协作中的上下文、工具与能力组合问题，形成对“生成式系统架构”的整体认识。

> 📌 **说明**：  进阶系统目标并不要求学习者否定或重构已有工作流成果，而是以其为基础，将其嵌入更高阶的系统结构中，实现能力叠加与视角升级。
### 1.3 课程设计原则

- **实践优先**：所有内容必须能执行，所有概念必须落回任务与产物。
- **工作流导向**：课程围绕工作流展开，而非碎片化知识。
- **任务驱动**：每Lesson=能力节点+任务闭环，无空讲、无纯理论。
- **可视化认知**：每知识点需配结构图或流程图≥1。
- **可复制示例**：每章节至少提供1个可直接运行Prompt示例。
- **开放协作**：任务提交、Review与作品沉淀基于**GitLink + PR模式**完成。
- **成果可展示**：最终成品是一个可运行智能体，而非文档或截图

## 2. 教学方法

### 2.1 教学理念

> 📌 **不是教你“让AI写”，而是教你“组织AI参与写作”。**

- AI不是答案提供器，而是协作节点。  
- AI读不懂模糊意图，但读得懂结构。
- 学习者不是被动接收知识，而是知识工作流的设计者。  
- 学习不是观看，而是实践驱动的产出行为。  
- 课程的终点不是作品，而是**可重复的方法沉淀**。  

### 2.2 教学方法

> 📌 **采用「任务闯关式 + Git协作式 + 作品输出式」结合**

- **任务制推进**：逐步构成学习闭环。
- **过程可追踪**：学习过程以Issue记录、PR提交成果。
- **生成式迭代**：每任务至少包含一次Prompt改进循环。
- **可视化理解**：所有知识点配导图/流程说明。
- **同伴互评与复盘**：促进反思与持续改进。

Git教学融入方式：

| 行为    | 执行方式                  |
| ----- | --------------------- |
| 提问与讨论 | 通过Issue提出问题并跟进交流      |
| 提交作业  | 通过Pull Request提交作品    |
| 协作修改  | 通过Review机制反馈、修改、Merge |
| 成果沉淀  | 优秀作品与工作流模板进入 Showcase |

## 3. 课程内容设计结构

课程内容统一结构模板：**Why → What → How → Example → Do → Output → Review**

对应教学逻辑：

|元素|作用|
|---|---|
|Why|建立动机，解释学习价值|
|What|核心知识点、概念、原则|
|How|步骤、流程、可执行操作清单|
|Example|示例/Prompt案例/演示|
|Do|必须完成的练习任务|
|Output|可交付作品或成果|
|Review|反思+沉淀模板|

## 4. 课程模块设计规范

每个Lesson必须包含：

- 明确可衡量的学习目标（不是“了解”，而是“能做”）
- 一个核心知识点 + 一个关键技能
- 至少一个可复制Prompt/案例/演示
- 一个可交付任务/作品产物
- 对应任务提交格式、提交路径与评估标准
- 在文末提供反思/复盘提示

Lesson推荐结构：

```markdown
## Lesson X 主题  
- 知识目标  
- 能力目标  
### 1.概念与原理  
### 2.方法与步骤  
### 3.Prompt示例  
### 4.练习任务（Do）  
### 5.产出要求（Output）  
### 6.复盘提示（Review）  
```

## 5. 任务设计方法

>📌 本课程采用**能力进阶型任务设计（Capability-Progressive Task Design）**。  任务不是孤立的练习，而是学习者能力演进路径上的**结构性节点**。


为匹配课程的能力进阶结构，课程任务分为三种类型。三者并非难度递增关系，而是**能力侧重点不同**，共同构成从“完成生成”到“理解系统”的连续路径。

- **基础生成任务**：关注 _“生成是否完成”_
- **系统嵌入任务**：关注 _“生成如何持续运行”_
- **协作扩展任务**：关注 _“生成如何被合理分工”_

|能力层级|对应任务类型|任务设计重点|
|---|---|---|
|L1–L2|基础生成任务|生成结构与流程完整性|
|L3–L4|基础生成任务|可复用性与方法沉淀|
|L5|系统嵌入任务|行动链与持续运行|
|L6|系统嵌入任务|运行环境与稳定性|
|L7|协作扩展任务|角色拆分与协议理解|
任务必须具备：

- 可执行
- 可输出#  1.核心原则：文档即产品，结构即思维

本课程所有文档不仅是教学内容的载体，其本身即应是“生成式思维”与“知识工作流”的**最佳实践范例**。文档应有清晰的产品意识，服务于明确的对象（学员、讲师、协作者），并通过自身的结构清晰度、表达准确性和视觉友好度，传递课程的核心思维模式。

## 6. 课程讲义与素材设计要求

讲义开发标准：

- 每章节至少配 **流程图/概念图/信息结构图≥1**
- 示例必须可复制运行（Prompt、脚本、结构化模板）
- 不得出现无任务、无产物的章节
- 每Lesson需提供任务提交规范与示例

素材类型与格式：

| 素材      | 格式                     |
| ------- | ---------------------- |
| 导图/流程   | SVG/PNG                |
| 讲义      | Markdown为主，可生成PDF      |
| Prompt库 | `.md`按主题归类             |
| 作品模版    | md/pdf/canva模版         |
| 任务提交样例  | students/sample/TaskXX |

## 7. 课程成功衡量标准

课程效果评估基于「学习者成果」「课程内容完成度」「生态沉淀」三大维度，形成可量化的成功闭环。

| 评估维度 | 衡量标准 | 达成条件 | 评价方式/数据来源 |
|---|---|---|---|
| **学习者成果完成度** | 学习者完成核心任务 | ≥80%学习者完成 Task03 最小闭环创作 | PR提交记录/产物数量统计 |
| | 知识工作流能力形成 | ≥60%学习者完成 Task04 个人工作流模板 | Template文件提交数 |
| | 作品公开输出情况 | ≥50%学习者完成 Task05 公开发布、带复盘链接 | Showcase区&外部链接数量 |
| | 作品质量与输出完整度 | 超过30%作品达到可展示标准 | Review记录、助教评分Rubric |
| **课程内容质量** | 讲义与任务设计完备度 | 所有模块符合 Why→What→How→Do→Output→Review 结构 | 内容检查清单 |
| | 示例与Prompt可执行性 | 每节至少提供1个可复制示例 | 讲义内容与examples目录审查 |
| | 任务闭环完整性 | Task01-05均可独立完成且环环相扣 | 内容流检查与学员体验反馈 |
| | 素材与可视化质量 | 每Lesson≥1张流程/知识结构图 | PPT/讲义检查 |
| **课程生态与可持续性** | 课程仓库活跃度 | Issue/PR持续增长，至少10条有效学习记录 | Git仓库统计 |
| | 成果沉淀质量 | 输出形成 Showcase/Workflow库 | 模板与作品数量 |
| | 课程可复用性 | 课程可重复开课/可扩展至第二版或进阶课 | 版本升级文档与复盘记录 |
| | 社区协作感 | 同伴评审、互评评论比>30% | PR评论记录 |

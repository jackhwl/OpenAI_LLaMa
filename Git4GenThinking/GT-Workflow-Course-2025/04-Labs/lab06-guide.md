# 第六章实验手册指南— 本地优先智能体运行环境实验

> 📌 **实验宗旨**：  本实验的目标不是“调用一个智能体工具”，而是亲手构建一个能够长期运行、可被理解、可被修正的智能体运行环境（Agent Runtime）**。

## 1. 实验目标与学习成果

本章实验是对前五章能力的系统性收束与跃迁。 在 Lab01–Lab05 中，你已经逐步完成了从Prompt到Workflow、从知识到行动的构建；而在第六章中，这些能力将首次被**放入一个真实可运行的系统环境中**。

- 以 **Obsidian** 作为本地知识与状态环境
- 通过**Cherry Studio**连接远程 LLM（Qwen / DeepSeek）
- 具备**Evaluate → Act → Reflect** 闭环
- 能够在真实知识工作中反复运行的 **Agentic Workflow 原型**

本实验的核心目标是让你从“提示词编写者”进化为“**智能体系统设计者**”。完成本实验后，你将实现：

1. **构建 PEAR 运行闭环**：在本地环境实践 **Perceive（感知）→ Evaluate（决策）→ Act（行动）→ Reflect（反思）** 的完整周期。
2. **实现本地优先架构**：理解“推理外包、状态内生”的原则，确保知识资产和运行状态保留在本地 Obsidian 中。
3. **掌握人机协同边界**：通过“人在回路”的模式，将 AI 的建议转化为受控的本地行动。    
4. **建立可持续演进系统**：利用反思机制修正智能体行为，使工作流具备“越用越稳”的特性。

---

## 2. 实验能力说明：前置要求与学习产出

### 2.1 前置技术能力要求

- **Obsidian 基础操作**：能够安装并使用桌面版 Obsidian，熟悉 Vault（库）的创建与管理。
- **Markdown 语法掌握**：理解 Markdown 二级标题（`##`）在分块逻辑中的应用，并能编写标准的 Markdown 文档。
- **元数据管理意识**：了解 YAML Frontmatter 的基本结构，能够手动配置和维护笔记的 Properties（属性）字段。
- **基础逻辑链接能力**：理解双向链接（`[[链接]]`）的原理，并能利用链接构建简单的知识网络。

### 2.2 核心技能产出

完成本实验后，你将具备以下核心能力：

|**核心技能**|**对应实验内容与能力描述**|
|---|---|
|**可治理知识结构化**|能够建立标准的目录结构（Notes/Concepts/Projects/Daily），实现知识的高效治理。|
|**语义分块与诊断**|掌握基于二级标题的语义分块（Chunking）策略，并能通过原生搜索进行分块合理性诊断。|
|**GraphRAG 构建与推理**|能够利用 Obsidian 的 Backlinks 和 Graph View 构建可遍历的语义网络，模拟 GraphRAG 的拓扑推理能力。|
|**行动链决策（Evaluate → Act）**|学会通过编写结构化的行动计划（Action Plan）来模拟智能体的决策过程，实现“先计划后执行”的稳健工作流。|
|**智能体反思与进化（Reflect）**|养成通过 Daily Note 进行行为回顾的习惯，利用标签化经验实现知识库的自我更新与进化。|
|**Agentic Workflow 原型设计**|能够整合触发器、状态评估、行动与反思，搭建出一个“人在回路”的本地智能助手原型。|

Lab06中形成的Agent Runtime认知，将在后续章节中被直接调用：

- 多 Agent 协作的前提，是 **运行环境标准化**
- MCP 协议的核心价值，是 **对运行环境的抽象与解耦**
- Agent 原生系统关注的，不是模型，而是 **环境、接口与协同机制**

## 3. 实验准备

### 3.1 学习准备

- **理解 RAG 与 GraphRAG 的核心差异**：需理解传统 RAG 依赖孤立的 Chunk 检索，而 GraphRAG 通过双向链接构建拓扑网络实现组合推理。
- **掌握“语义分块”黄金规则**：学习如何利用 Markdown 的二级标题（`##`）作为知识分块（Chunking）的自然边界。
- **熟悉 Agentic Workflow 闭环**：理解“检索 → 评估 → 行动 → 反思”的完整逻辑路径。
- **对齐知识存储与功能映射**：明确笔记目录（Memory）、项目目标（Goals）与日记（Reflect）之间的逻辑对应关系。

### 3.2 工具与环境准备

| 工具                | 用途定位                                                |
| ----------------- | --------------------------------------------------- |
| **Obsidian**      | Agent 的本地运行环境（Memory / State / Action / Reflection） |
| **Cherry Studio** | Agent 的推理与规划前端（Evaluate / Reflect）                  |
| **远程 LLM**        | 推理能力（如 Qwen / DeepSeek）                             |

请确认：

- Cherry Studio 已安装并可正常使用，详情请参考[Cherry Studio安装和配置手册指南](./../06-Tools/cherry-studio-intallation-guide.md)
- 已配置至少一个可用的远程模型
- 能进行多轮对话与结构化输出


Cherry Studio 在本实验中的作用相当于：

- 生成决策建议（Evaluate）
- 辅助反思总结（Reflect）

完成以上准备后，你将具备：

- 一个可控的本地 Agent 运行环境
- 一个清晰分工的推理接口
- 一个适合持续运行与反思的实验条件

## 4. 实验流程：构建本地智能知识助手

### 4.1 任务说明

本实验统一采用**PEAR 行动框架**：Planning → Evaluate → Act → Reflect：

| 阶段           | 核心问题             | 角色定位      |
| ------------ | ---------------- | --------- |
| **Planning** | 要解决什么问题？不解决什么问题？ | 人主导       |
| **Evaluate** | 在当前知识环境下，应该怎么做？  | Agent（模型） |
| **Act**      | 计划是否可行？真实执行效果如何？ | 人在回路      |
| **Reflect**  | 本轮行动哪里有效？哪里需要调整？ | 人 + Agent |

在 Lab06 中，你将完成以下任务：

1. 基于已有 Vault，明确一个可重复的知识工作目标（Planning）
2. 让 Agent 在明确边界下生成行动计划（Evaluate）
3. 在真实知识环境中人工执行该计划（Act）
4. 记录反思并调整下一轮行动方向（Reflect）

请选择一个真实、可重复的知识工作任务，并满足以下条件：

- 基于你当前 Vault 中已有的知识内容
- 不依赖外部系统或复杂工具
- 允许人工执行与调整

推荐示例：
- 每周知识整理与结构优化
- 项目学习路径回顾
- 概念体系查漏补缺

不推荐示例：

- 一次性内容生成
- 纯创作型任务
- 高度自动化任务

## 4.3 实验步骤

### 4.3.1 任务一：Planning —— 明确目标与行动边界

**目标**：  为 Agent 明确 _要解决什么问题_、_不解决什么问题_，避免无效行动。

**操作步骤**：

1. 打开 `01-agent-action-run.md`， 在文件顶部新增 **Planning 区块**，按以下模板填写：

```markdown
## Planning

**目标（Goal）**：
- <一句话说明本次 Agent 要完成的事情>

**作用范围（Scope）**：
- 涉及的知识范围：
- 不涉及的内容：

**完成标准（Done Criteria）**：
- 满足哪些条件，才算“本轮任务完成”
```

### 4.3.2 任务二：Evaluate —— 生成 Agent 行动计划

**目标**：  基于你当前 Vault 中的真实知识环境，生成一个可执行的行动计划。

**操作步骤**：

1. 打开 **Cherry Studio**
2. 选择你已配置好的远程模型
3. 输入以下提示`01-agent-action-run.md `（可微调任务内容，但保持结构）：

```markdown
你是一个智能体规划器。
请基于我当前的 Obsidian 知识环境，完成以下任务：

目标：<填写你的真实任务，例如：每周知识整理>
要求：
- 输出一个清晰的行动计划
- 每一步说明：做什么 + 为什么
- 不要自动执行，只给出计划
```

4. 检查输出是否为**步骤化计划**（而非长段解释）

**结果记录**：将最终行动计划整理并写入`01-agent-action-run.md`

```markdown
## Evaluate

- Step 1:
- Step 2:
- Step 3:
```

### 4.3.3 任务三：Act —— 人机回路执行行动计划

**目标**： 在真实 Vault 中，**人工执行** Agent 给出的行动计划。

**操作步骤**：

1. 打开 `01-agent-action-run.md`
2. 按步骤逐条执行：
    - 新建 / 修改 / 重组笔记
    - 调整知识结构或链接
3. 在行动计划中标记执行状态，例如：

```markdown

### Act

- [x] 合并重复概念
- [ ] 重写项目说明`
```

### 4.3.4 任务四：Reflect —— 记录反思与调整方向

**目标**：  对刚才的 Agent 行为进行反思，为下一轮运行提供依据。

**操作步骤**：

1. 回到 **Cherry Studio**
2. 输入以下反思提示：

```markdown
请基于刚才的执行过程进行反思：
1. 哪一步最有效？
2. 哪一步成本最高或不必要？
3. 下一轮应如何调整 Planning？
```

3. 将反思结果整理为**简要条目**

至少包含：

- 一个问题发现
- 一个明确的改进方向
-
**结果记录**：将反思内容写入 `01-agent-action-run.md`

```markdown
## Reflect

请反思刚才的行动过程：
- 哪些步骤是多余的？
- 哪些地方可以结构优化？
- 下次应如何调整行动计划？
```

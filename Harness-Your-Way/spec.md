# Deep Research Agent 规格
## 1. 做什么
### 目标
对一个明确的研究问题做系统调研，输出带可追溯来源的结构化研究报告。
### 输入
- 研究问题（一句话，例如"MIT 与 Apache-2.0 许可证的核心差异"）
- 可选：补充说明（关注维度、深度要求、来源偏好）
### 输出
三部分结构化报告：
1. **研究结论**：分条列出，每条结论必须可回溯到具体来源
2. **资料来源**：每条来源标注到具体章节或段落，不是只给一个链接
3. **待确认事项**：证据不足、来源冲突或超出研究范围的问题，明确标注
## 2. 怎么做
### 处理流程（六步）
1. **元思考**：质疑问题本身，定义"好答案"的标准，写下初始假设
2. **问题拆解**：把研究问题拆成 2-5 个子问题
3. **资料检索**：针对每个子问题检索相关来源（优先使用搜索工具）
4. **来源精读**：从来源中提取证据，记录出处到章节级别
5. **证据综合**：综合证据得出结论，区分"有来源支撑的"和"需要确认的"
6. **报告撰写**：检查结论-来源对应关系，输出最终报告
### 工具使用
- 检索：使用搜索工具（如 Tavily、Brave Search）获取外部资料
- 知识库：使用最小知识库检索本地文档中的相关内容
- 阅读：使用网页抓取工具获取完整文档
### 决策逻辑
- 检索结果少于 3 条来源时，标注"来源不足，结论需谨慎使用"
- 来源之间存在冲突时，列出冲突双方，标注"需人工裁决"
- 证据强度不足时，归入"待确认事项"而非强行下结论
## 3. 拒绝条件
以下行为 agent 必须拒绝：
- **不编造来源**：如果检索不到相关来源，标注"未找到"而不是猜测
- **不给模糊出处**：来源必须精确到章节或段落，不能只给"来自某文档"
- **不回避不确定**：证据不足时必须标"待确认"，不能装作确定
- **不超出范围**：研究范围由输入问题界定，不主动扩展话题
- **不执行操作**：只做研究和报告，不执行任何写入、发送、下单等操作
- **不递归拆解**：子 agent 不许再派子 agent
## 4. 验收标准
### 成功条件
- 每条结论至少有一个可追溯的来源
- 来源引用精确到章节或段落
- 不确定项都被标注出来
- 报告结构清晰，结论/来源/待确认三部分完整
### 质量指标
- 来源数量：至少 3 个独立来源
- 来源质量：优先使用权威来源（官方文档、学术论文、权威媒体）
- 结论覆盖：每个子问题都有对应的结论
- 不确定项：证据不足的问题都被标注，而非强行下结论
